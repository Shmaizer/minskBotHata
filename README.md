# Telegram-бот мониторинга аренды квартир в Минске

**Фильтры:** 1–2 комнаты, до 1100 BYN в месяц. **Интервал опроса:** 60 секунд.
**Источники:** Kufar, Onliner, Domovita.

## Что делает проект

- При запуске проверяет доступные объявления, затем повторяет проверку каждые 60 секунд.
- Применяет фильтры: 1–2 комнаты, цена до 1100 BYN в месяц.
- Для Kufar и Onliner не проверяет дату публикации; для Domovita принимает объявления с датой от вчерашних 00:00 по Минску.
- Сохраняет успешно отправленные ссылки в SQLite, чтобы не отправлять их повторно.
- Отправляет карточку с названием, ценой, комнатами, адресом, ближайшим метро (если оно указано), общей площадью, источником, ссылкой и временем обнаружения ботом. Если адрес или площадь не распознаны, это явно отмечается. Фотография прикрепляется, когда доступна в карточке.
- Поддерживает команды `/start`, `/status`, `/chatid`, `/check`, `/pause`, `/resume`.

## Ограничения источников

- **Kufar:** используется публичная страница поиска. Если сайт отвечает HTTP 403/429, бот пропускает источник и не обходит ограничение.
- **Onliner:** публичный HTML `r.onliner.by/ak/` не содержит карточек, а путь `/sdapi/` на этом хосте запрещён текущим `robots.txt`, поэтому бот к нему не обращается. Вместо этого есть экспериментальный адаптер для отдельного хоста `ak.api.onliner.by/search/apartments`, упомянутого в открытом стороннем коде, но не в официальной публичной документации Onliner. Перед запросами бот проверяет `https://ak.api.onliner.by/robots.txt` и каждый фактический URL; запрещённые параметры не отправляются. При запрете пути, ошибке robots.txt или ответе 401/403/429 источник пропускается. Это не гарантированно поддерживаемая интеграция: если endpoint или правила не позволяют опрос, используйте только канал, разрешённый Onliner.
- **Domovita:** используется открытая страница долгосрочной аренды; бот просматривает до `DOMOVITA_PAGES` страниц (по умолчанию 3) при запуске, а затем первую и дополнительные по очереди.

Разметка сайтов может меняться; даты, адреса, станции метро и площадь распознаются только если они доступны в открытом HTML. Не применяются обход CAPTCHA, авторизации, прокси-ротация, подмена отпечатка браузера или другие способы обхода ограничений. Частота проверки 60 секунд не гарантирует обновления объявлений самими сайтами.

## Установка

Требуется Python 3.11+.

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

## Настройка Telegram

1. Откройте `@BotFather`, выполните `/newbot` и получите токен.
2. Вставьте токен в `TELEGRAM_BOT_TOKEN` в `.env`. Не отправляйте его третьим лицам.
3. Добавьте бота в группу и убедитесь, что у него есть право отправлять сообщения. В `.env` временно оставьте `TELEGRAM_CHAT_ID=` пустым.
4. Запустите бота, отправьте в группе `/chatid` (или `/chatid@ИмяВашегоБота`). Скопируйте показанный ID — у супергрупп он обычно начинается с `-100`.
5. Остановите бота сочетанием `Ctrl+C`, вставьте ID в `TELEGRAM_CHAT_ID` файла `.env` и запустите бота заново. После перезапуска карточки будут отправляться в группу.
6. Проверьте параметры `MAX_PRICE_BYN=1100`, `ROOMS=1,2`, `POLL_SECONDS=60`.
7. URL источников уже заполнены. Если какой-либо источник запрещает автоматический доступ, удалите его URL или оставьте поле пустым.

## Запуск

```powershell
python bot.py
```

При первом запуске без `TELEGRAM_CHAT_ID` бот не отправляет карточки, но отвечает на `/chatid`, чтобы можно было узнать ID группы. После указания ID и перезапуска бот сразу сканирует доступные страницы и присылает ещё не отправленные карточки со вчерашних 00:00 по Минску в выбранный чат. Для ручной проверки используйте `/check`; диагностика и счётчик сохранённых ссылок доступны через `/status`. Команда `/chatid` показывает ID текущего чата, включая группу. Смотрите вывод терминала: там будет указано, сколько карточек распознано на каждом источнике или почему источник пропущен.

## Важные детали реализации

- Цена извлекается только как сумма в BYN/белорусских рублях; цены в долларах и евро не конвертируются.
- Объявления без распознанных цены или количества комнат не отправляются — это снижает число ложных совпадений.
- Ссылка помечается просмотренной после успешной отправки, чтобы сбой Telegram не приводил к потере уведомления.
- Для Kufar и Onliner дата публикации не требуется; для Domovita объявление без распознанной даты пропускается.
- Для круглосуточной работы используйте VPS и менеджер служб с автоперезапуском. Не публикуйте `.env` и `listings.sqlite3`.


## Поиск объявлений за вчерашний день и диагностика

- При запуске бот просматривает до `DOMOVITA_PAGES` страниц Domovita (по умолчанию 3), затем проверяет первую страницу и по очереди одну дополнительную страницу на каждом цикле. Страницы используют публичный параметр `?page=N`.
- Сбор принимает объявления с датой публикации от вчерашних 00:00 по времени Минска до текущего момента. Объявления без распознанной даты пропускаются.
- В журнале PowerShell ищите строки `Kufar:`, `Onliner:` и `Domovita:`. Они показывают HTTP-ошибки или количество распознанных карточек. После итоговой строки проверки выводится `Диагностика дат [источник]` — сколько карточек и сколько дат распознано на каждом сайте. Итог также разделяет отсутствие цены, превышение бюджета и неподходящее число комнат.
- Если `Kufar` отвечает 403 или 429, бот пропускает его, не обходя ограничения. Для Onliner смотрите строки `Onliner API:`: бот сообщает результат проверки собственного `robots.txt`, какие параметры были запрещены, сколько карточек получено и распознано либо почему источник пропущен. Запрос к `/sdapi/` на `r.onliner.by` не выполняется.
